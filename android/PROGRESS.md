# Android progress

Read this first in every session. A row is "done" only with evidence: the
command that was run and what it printed, or a screenshot path. "Tests pass"
alone is not evidence that a feature works (see the quality rules in
`PLAN.md`, "Bağlayıcı kalite kuralları").

Sources of truth:

- Design: `docs/android/mock/index.html`, its reference images in
  `docs/android/mock/ref/<screen>-<theme>.png` (370 x 824 CSS px), the element
  inventory in `docs/android/mock/inventory/<screen>.json` and the tokens in
  `docs/android/mock/tokens.json`. Regenerate with `tools/mockref`.
- Behaviour: `docs/android/PORTING.md` (desktop code to port, with line
  references) and the desktop Go code itself.
- Font: `fonts/GoogleSans.ttf` (variable, 100-1000), the same file the mock
  uses.

Toolchain (in the home directory, no sudo): JDK 21 at
`~/.local/share/jdks/jdk-21*`, Android SDK at `~/Android/Sdk`, AVD `meiro36`
(android-36, x86_64, google_apis). APKs are built here and installed with
`adb`; they are never committed or published.

## M4e: deviations, for the owner

- **The reasons are the desktop's two, in the mock's Turkish.** The desktop's ranking gives only "New to you, like X" and "Because you listen to X", and stores that English text in the item's `note` (the desktop shows it as it is). The phone ranks the same way and stores the same English text (so the desktop keeps working), and shows "Yeni sanatçı · X ile benzer" and "X ile benzer" (the mock's own wording for these two). The mock's other reasons ("Fikret Kızılok'u sık dinliyorsun", "… dinleyenler de dinliyor", "Gece Sürüşü listene benziyor", "Son bir ayda 14 kez dinledin") have no source in the algorithm and never appear; a reason the phone does not know is shown as it is.
- **Kind line**: "Bugün için · N parça · her sabah yenilenir"; "Dün için" for yesterday's mix, "3 Kasım için" for an older one (the mock shows only today). N is the real number of tracks.
- **Rows** use the playlist row: the source logos the track has, the link button for tracks with no MusicBrainz link (all of a fresh mix, since MusicBrainz linking is M6), "artist · length" with the length only when known: YouTube Music's related page gives no length, so a generated mix's rows show the artist alone (the mock's "Fikret Kızılok · 4:22").
- **The page's cover** is the mix's gradient (the mock's `.big` with the `.mix` background), not track pictures. The Library row keeps the list cover rule (first track's picture), as the other rows do; the mock draws a gradient there.
- **Reached from** Home's Daily mix card and the Library's Daily mix row (the mock's two `open-mix`). The page keeps the tab it was opened from selected. The mix page with no mix stored goes back.
- **Generation (ported in this milestone, PORTING.md 5.2-5.4)**: same seeds (top 8 artists' latest played songs), budgets (10 YouTube Music, 3 SoundCloud per run), pauses (1.5 s / 3 s before each request not in the cache), 24 h related cache (dropped after 7 days; a file in the app's files dir), ranking (30 picks, 30% new, 2 per artist in any 10, a week as "just played", salt = local date), at least 5 picks, once a day, the shared list `bab208cb-…` named "Daily mix" replaced (never added to), an older mix under another id deleted, adoption of another device's mix made today, sent through the outbox when signed in.
